# Crypto Research Skill

两种模式：
- **扫描模式**（Step 0 → Step 0B → 结论）：用户没有指定具体代币，想发现机会
- **单项目模式**（Step 1 → Step 8）：用户指定了具体代币/项目，做完整投研

每步为必做项，不可跳过。工具调用失败须显式标注，不补脑造数。

---

### Step 0 · 市场扫描模式（无特定标的时启动）

当用户要找 meme/alpha 机会，而非分析特定代币时，执行此步骤。

#### Step 0A · 宏观情绪判断

先确认当前流动性窗口是否开放，再决定要不要扫标的。

调用 `get_crypto_market` + `get_funding_rate` 对大盘（BTC）和目标链（SOL / BNB，
视用户关注赛道而定）拉取：价格趋势、24h 成交量、funding rate。

判断框架：
- **窗口开放**：主链稳住或上涨，成交量持续放大，funding rate 未极端偏正
- **窗口关闭**：主链下跌或成交量萎缩，或 funding rate 极度拥挤

若窗口关闭，直接给出判断并说明原因，不进行后续扫描。

#### Step 0B · 一手发现数据

宏观窗口确认后，使用 `web_fetch` 获取链上**一手热度数据**，而非二手摘要。

数据源的选择原则：
- **Solana meme**：查 DEX 聚合器的实时成交排行（DexScreener、Birdeye 等均可），
  以及 meme 启动平台的新品榜（Pump.fun、LaunchLab 等）
- **Binance Alpha**：查 Binance Alpha 官方页面或公告，获取近期上线/预告项目列表
- **通用链上热度**：优先选择有公开 API 或可直接抓取 HTML 的平台；
  数据要求：近 24h / 近 6h 成交量排序，或平台内置的热度评分

具体 URL 选择：用你已知的该平台当前可访问地址；若 fetch 失败，换同类平台重试。
不要因为某个 URL 失败就放弃整个扫描——换平台，继续。

#### Step 0C · 候选评估与输出

对扫描到的代币，按以下维度评估（全部是定性判断，不是硬阈值）：
- **流动性是否足以进出**（买卖价差、池子深度）
- **成交活跃度趋势**（是否加速，还是已经开始退潮）
- **筹码结构初步判断**（是否有钱包高度集中的迹象）
- **叙事是否可传播**（meme 的核心：能不能一句话讲清楚）

输出结构：

```
## 市场扫描（{链} · {日期}）

### 宏观窗口：[开放 / 关闭 / 中性]
[核心数据 + 一句判断]

### 当前值得关注的候选（基于一手数据）

| 代币 | 市值规模 | 活跃度判断 | 叙事 | 主要风险 |
|------|----------|----------|------|----------|
| ... | | | | |

### 整体判断
[当前赛道热度、入场时机、最大系统性风险]
```

完成后停止；不要在扫描模式中自动展开完整单项目分析。

### Step 1 · 项目基本面

**目标：搞清楚这个项目是什么、解决什么问题、凭什么存在。**

首先调用 `corpus_search` 查询该项目 / 赛道（用项目名、代币名、赛道关键词）。
同时调用 `web_fetch` 抓取官方文档或 CoinGecko/Messari 项目页面补充以下信息：

| 维度 | 内容 |
|------|------|
| 项目定位 | 一句话描述（不超过 20 字） |
| 解决的核心问题 | 现有方案的缺陷 + 本项目的改进点 |
| 技术路线 | L1/L2/协议层/应用层；共识机制（PoW/PoS/DPoS）；VM 类型 |
| 赛道 | DeFi / NFT / L1 / L2 / RWA / AI / DePIN / Meme 等 |
| 主网状态 | 测试网 / 主网已上线 / 上线时间 |
| 团队背景 | 创始人履历（匿名 / 公开）；有无知名 VC 背书 |

### Step 2 · 代币经济学

**这是 crypto 分析的核心差异项，必须完整覆盖。**

| 字段 | 来源 | 填入 |
|------|------|------|
| 总供应量（Max Supply） | Coingecko / 官网 | |
| 当前流通量（Circulating Supply） | Coingecko | |
| FDV（全稀释市值）| 总供应 × 当前价格 | |
| MC/FDV 比率 | 流通市值 / FDV | |
| 解锁计划 | 下 6/12 个月预期释放量 % | |
| 主要持仓方 | 团队 / 投资人 / 社区 / 生态 各占比 | |
| Token Utility | 治理 / 质押 / Gas / 手续费折扣 / 其他 | |
| 通胀 / 通缩机制 | 是否有销毁 / 回购；年通胀率 | |

**MC/FDV 风险判断：**
- MC/FDV < 0.3：解锁压力高，须说明解锁节奏
- MC/FDV 0.3-0.7：中性
- MC/FDV > 0.7：流通基本充分

### Step 3 · 市场数据

调用以下工具获取量化数据：

```
get_crypto_market(symbol="XXX")          # 市值、流通量、价格、24h涨跌、7d涨跌
market_quote(tickers=["BINANCE:XXXUSDT"], market="crypto")  # 报价 + 技术评级
get_candlesticks(symbol="XXX", interval="1w", limit=52)          # 近 1 年周 K
```

Binance 没有上市（返回 400）时自动使用 CoinGecko fallback（工具内置，无需手动处理）。

从数据中提取并报告：
- 当前价格 vs. ATH：折价幅度
- 当前价格 vs. ATL：涨幅倍数
- 近 30 天价格走势（趋势 + 关键支撑阻力位）
- 日均成交量 vs. 市值比（>5% 为活跃，<1% 为低流动性）
- Funding Rate（如有永续合约）：`get_funding_rate(symbol="XXX")` —— 正值代表多头拥挤

### Step 5 · 链上数据（best-effort）

链上数据是 crypto 基本面的核心信号，优先尝试获取：

- 调用 `web_fetch` 抓取 DefiLlama（TVL 趋势）
- 调用 `web_fetch` 抓取 Dune Analytics 公开看板（活跃地址、交易量）
- 调用 `corpus_search` 查找已沉淀的链上分析

**若数据获取失败**：明确标注"[链上数据不可用]"，并在不确定性中说明这对判断
的影响程度（高/中/低）。不捏造链上数据。

核心指标含义（如果获取到）：
- TVL（Total Value Locked）：DeFi 协议的资产规模，增长 = 使用增加
- DAU / 活跃地址数：网络实际使用率
- 手续费收入：协议真实创造的价值（对比 Token 市值 = P/E 类比）
- 开发者活动（GitHub commits）：项目是否仍在积极建设

---

### Step 6 · 多空论点

**Bull Case（支撑上涨的论点）：**  
列 2-3 条，每条须可证伪（有具体催化剂 / 时间节点 / 数据变化阈值）。
例："主网升级（Q3 2025）如果成功降低 gas 50%，TVL 有望进入 Top 10"。

**Bear Case（steelmanned 反方）：**  
列 2-3 条最强版本，必须包含：
1. 代币解锁/通胀带来的供应侧压力
2. 赛道竞争（为什么竞品可能胜出）
3. 监管 / 流动性宏观风险

### Step 7 · 估值参考

Crypto 没有 DCF 的统一范式，但以下框架可酌情使用（标明适用条件）：

**NVT Ratio（Network Value to Transactions）**  
适用：有链上转账数据的 L1 / 支付类代币  
NVT = MC / 日链上交易量；高 NVT = 网络价值未被交易活动支撑

**P/Fee（类 P/E）**  
适用：有真实手续费收入的 DeFi 协议  
P/Fee = FDV / 年化手续费收入；参考 Uniswap ~20x，Aave ~10-15x

**相对估值（赛道内 FDV 对比）**  
对比同赛道头部协议的 FDV/TVL 或 FDV/活跃地址；判断标的是否显著偏贵/偏宜

若以上三种框架均无适用数据，显式说明"当前阶段无法基于基本面定价，定价
完全由市场情绪和叙事驱动"，并在结论中相应调低置信度。

### Step 8 · 研究结论

```
**[代币名称 / Ticker]  研究结论**

**项目一句话**：[定位]

**市场数据**：价格 $X | MC $XB | FDV $XB | MC/FDV X% | ATH 折价 X%

**代币经济学评级**：[健康 / 中性 / 有压力]
核心理由：[MC/FDV + 解锁节奏 + utility 强度]

**竞争格局**：[赛道领头 / 第二梯队 / 边缘玩家]

**估值判断**：[贵 / 合理 / 低估 / 无法定价]  置信度：[高 / 中 / 低]

**最值得跟踪的 3 个信号**：
1. [信号] → 若发生，支持 [bull/bear]
2. [信号] → 若发生，支持 [bull/bear]
3. [信号] → 若发生，支持 [bull/bear]

**信息层级**（discipline §1）：
- 事实：[工具获取的数据]
- 推断：[基于数据的逻辑推导]
- 推测：[依赖叙事或假设的部分，不确定性最高]
```
