# web-research — 求证纪律的执行指南

system prompt 已经讲了求证纪律("先搜后答")的原则。这个 skill 是具体怎么执行。

## 一、什么时候搜

**必搜**:
- 具体股票代码、公司当前业务、最新财报数字
- 价格、汇率、利率(任何含数字的"当前状态")
- 新闻事件、人物动作、监管政策
- 日期 / 时间("最新 / 近期 / 当前" 三连词)
- 用户给的链接 / 截图里没有上下文的术语

**不用搜**:
- 你的分析、推理、判断、对比
- 历史已知事实(物理 / 数学常数、知名经典案例)
- 用户已经在 chat 里给的事实

## 二、search 怎么写 query

- **关键词组合**,不写完整问句。`苹果 2026 Q1 营收` 比 `苹果公司今年第一季度的营收是多少` 好。
- **加时间限定词**:`2026`、`最新`、`近期`、`Q1`。否则容易拿到 2-3 年前的 cache。
- **中英都试一遍**:中文 query 命中中文媒体,英文 query 命中 Bloomberg / Reuters 类一手源。
- 0 hits / 全是不相关 → 改 query 重试 1-2 次,再不行如实说"搜不到"。

## 三、fetch 怎么用

- search 给的是 摘要 + URL。一手源拿不到的关键事实(具体数字、原话引用)→ web_fetch 该 URL 拿全文。
- **不要无脑全 fetch**:每次 fetch 都是 latency + context tokens。先看 search 摘要够不够答。
- fetch 来的页面带 markdown(已转换),回答时引用要带 URL。

## 四、产出格式

- 数字 / 引用 → 后面跟 `(来源: <URL>)`。
- 多源对比时显式列出 :"Bloomberg 说 X(URL),华尔街日报说 Y(URL)。"
- 搜不到 → 明说,不要硬编。用户问"特斯拉今天股价",搜不到就说"未搜到当前 quote",**不要给训练里的旧数**。

## 反模式

- 仅靠训练知识答时效性问题(用户最痛的点)。
- search 一次没好结果就放弃,直接给训练答案。
- fetch 完不引用 URL,后面用户没法核对。
