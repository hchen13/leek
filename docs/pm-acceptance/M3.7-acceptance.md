## DR4 详分析(唯一非 end_turn case)

DR4 不是 bug — 是 M3.3-M3.7 整条容错链的教科书示例:

1. 主 agent 委派 `task("deep-review", "招商银行...")`
2. deep-review subagent 跑了一阵,撞 `$5.00 cost cap`(M3.6 加的 per-subagent cap)→ stop_reason=`subagent_cost_cap_exceeded`
3. 主 agent 接管,直接调 market_quote / get_financials / web_fetch 等工具,自己复盘
4. 主 agent 跑到 540s 时 codex stream 进入静默
5. M3.3 `idle_timeout=180s`(substantive-only)触发 → drop stream + 抛 fatal
6. M3.5 retry 触发 1 次(`MAX_ATTEMPTS=5`,但 substantive latch 限制只重试 1 次因为已经 yield 过 TextDelta)→ 仍 silent
7. **M3.7 §D fault-tolerant final 触发**:把 380 字符已 yield assistant text 作为 final 还给 user + 加 "本回合中断 ... 可重试本回合或调 Settings 中 reasoning effort" footer

user 视角看到的 380 字内容已经覆盖:
- 调用方法说明
- 招行实时报价(¥36.94)
- 估值数字(PE 6.2x / PB 0.8x / 股息 5.5%)
- 结论先行("高质量资产 + 高 ROE + 中高股息")
- 长期价值判断

完全可用的回复 — user 点"重试本回合"就能续。
