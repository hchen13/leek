## Scope

### A. Backend — config file 读写 + API

#### A.1 Config 模块

新建 `crates/gateway/src/config.rs`:

```rust
// 单一 Config struct,序列化为 ~/.leek/config.json。
// 所有字段 Optional,缺省 = 使用 default(对齐 guards.rs 的默认值)。
// JSON 格式(无外加依赖,serde_json 现成)。

pub struct Config {
    pub idle_timeout_secs: Option<u64>,           // 默认 90;0 = 关
    pub wall_clock_secs: Option<u64>,             // 默认 1800;0 = 关
    pub max_iterations: Option<usize>,            // 默认 None
    pub cost_cap_usd: Option<f64>,                // 默认 None(不限)
    pub doom_loop_threshold: Option<usize>,       // 默认 3
    pub auto_compact_threshold: Option<f32>,      // 默认 0.90
    pub context_window: Option<i64>,              // 默认 None(用 model 表)
    pub max_cost_usd_per_turn: Option<f64>,       // 别名同 cost_cap_usd,迁移到这个新名
    pub web_search_enabled: Option<bool>,         // LEEK_WEB_SEARCH 现状
}

impl Config {
    pub fn load() -> Result<Self> { /* 读 ~/.leek/config.json,不存在则返 default */ }
    pub fn save(&self) -> Result<()> { /* 写 ~/.leek/config.json,创建目录 */ }
    pub fn path() -> PathBuf { /* ~/.leek/config.json */ }
}
```

- 文件路径:`~/.leek/config.json`,通过 `dirs` crate(已是常用依赖,如未引入则加)或 `std::env::home_dir`
- 缺失文件 → 返 default(空 Config),**不报错**
- malformed JSON → 报 warning log,返 default(graceful 退化)
- 写入时原子(先写 `.tmp`,再 rename)

#### A.2 Guards 加载链路改写

`crates/gateway/src/agent/guards.rs` `GuardConfig::from_env()` 改为 `GuardConfig::resolve()`,
按 **env var > config file > built-in default** 优先级合并:

```rust
impl GuardConfig {
    pub fn resolve(config: &Config) -> Self {
        Self {
            idle_timeout:    duration_resolve("LEEK_IDLE_TIMEOUT_SECS", config.idle_timeout_secs, 90),
            wall_clock:      duration_resolve("LEEK_WALL_CLOCK_SECS", config.wall_clock_secs, 30 * 60),
            max_iterations:  usize_resolve("LEEK_MAX_ITERATIONS", config.max_iterations),
            cost_cap_usd:    f64_resolve("LEEK_COST_CAP_USD", config.cost_cap_usd),
            doom_loop_threshold: usize_resolve_with_default("LEEK_DOOM_LOOP_N", config.doom_loop_threshold, 3),
            auto_compact_threshold: f32_resolve("LEEK_AUTO_COMPACT_THRESHOLD", config.auto_compact_threshold, 0.90),
            context_window:  i64_resolve("LEEK_CONTEXT_WINDOW", config.context_window),
        }
    }
}
```

`AppState::new` (或等价初始化处) 改为加载 config 一次,放进 AppState (`Arc<RwLock<Config>>` 让 PATCH 能改)。

#### A.3 API endpoints

`crates/gateway/src/api/` 新增 `settings.rs`:

- `GET /api/v1/settings` → 返当前 `Config`(JSON)
- `PATCH /api/v1/settings` → body 是部分 `Config`,merge 到当前并 save 到磁盘;**热生效**(AppState 里
  的 `Arc<RwLock<Config>>` 改字段,下个 turn 用新值)
- response 包含 `effective`(actual values being used after env override merge,只读)和 `config_file`
  (磁盘上的 raw values),让前端能区分"用户设了什么"vs"实际生效什么"

请求示例:
```bash
curl -X PATCH http://localhost:8964/api/v1/settings \
  -H 'content-type: application/json' \
  -d '{"cost_cap_usd": 5.0}'
```

#### A.4 cost cap 软停体验完善

cost cap 已经会 set `stop_reason = "cost_cap_exceeded"`,但目前 **没有专门 event**。加一个
`turn_cost_capped` event(参考 events.rs 现有事件模式):

```rust
// crates/gateway/src/agent/events.rs
pub enum Event {
    // ...
    TurnCostCapped { cap_usd: f64, actual_cost_usd: f64, iter_count: u32 },
}
```

在 mod.rs:159 触发时 emit 这个 event(在 `stop_reason = "cost_cap_exceeded"` 之前)。

### B. Frontend — Settings 页面

#### B.1 路由 / 入口

不引入 router(SolidJS 当前 app 是单页)。简单做法:
- 顶部导航加一个齿轮 ⚙ 图标按钮
- 点击切换右侧栏(或 modal)显示 Settings 面板
- 不动现有三栏布局(Chat / Canvas / Corpus Brain),settings 作为 overlay

可选:用 Solid Router 加 `/settings` 路由。**executor 选简单的一种**,优先 modal/overlay 模式
(无依赖、scope 小)。

#### B.2 Settings.tsx 组件

字段表单,每个字段:label + input + "当前生效"显示(如果被 env var override 则显示"⚠ 被环境变量
override")。

| 字段 | input 类型 | default 显示 |
|---|---|---|
| Cost cap (USD per turn) | number,允许小数 | `0 = 不限制` |
| Idle timeout (秒) | number | `90` |
| Wall clock (秒) | number | `1800` |
| Max iterations | number | `空 = 不限制` |
| Doom loop threshold | number | `3` |
| Auto compact threshold | number 0-1 小数 | `0.90` |
| Context window | number | `空 = 用 model 默认` |

底部:**保存**按钮(PATCH `/api/v1/settings`)+ **重置为默认**按钮(PATCH 空 config) +
"当前 config 文件路径:`~/.leek/config.json`" 文字提示

加载:页面打开时 `GET /api/v1/settings`,填表单;保存后再 GET 一次刷新"当前生效"标记。

#### B.3 cost cap 触发警告条

`frontend/web/src/Chat.tsx`(或 turn 渲染处)识别 `assistant_done.stop_reason = "cost_cap_exceeded"`,
在该 turn 末尾显示警告条:

```
⚠️ 本轮研究达到预算上限 ${cap}（实际 ${actual}），已在第 {iter} 步停止。
   再问一句可以继续 / 或在 Settings 调整预算 [打开 Settings →]
```

样式:醒目但不阻碍阅读(黄色背景 + 边框,固定在 turn 下方)。

### C. 不做

- **不引入 Solid Router 之外的 routing 框架**(尽量用 conditional render)
- **不做 yaml 配置**(JSON 够用,无依赖)
- **不删 env var 路径**(env var 仍 override config file,便于 CI / debug)
- **不做 cost cap 之外新 guard**(机制完整时再扩)
- **不做 "resume same turn"**(用户超 cap 后想继续,自己发新 prompt 接力即可)
- **不动 corpus / agent 行为**(只是 settings 入口)

### D. 单测

Backend:
- `config.rs`:save → load round-trip;malformed JSON 退化 default;路径解析
- `guards.rs`:env > config > default 优先级,3 个分支各覆盖
- `api/settings.rs`:GET 返当前;PATCH 部分 merge;PATCH 之后 file 已 update + AppState live 改

Frontend(如果有 test 设施):至少 settings form 提交后 PATCH body 形状正确。

### E. 异常处理

| 情况 | 怎么办 |
|---|---|
| `~/.leek/` 目录不存在 | save 时自动创建,load 时返 default |
| `~/.leek/config.json` malformed | warn log + 返 default,不阻塞启动 |
| PATCH body 不是合法 JSON | 返 400 + 错误描述 |
| PATCH 设了不合法值(如 `cost_cap_usd = -1`) | 返 400 + 字段错误清单 |
| 前端 Settings 页面 fetch 失败 | 显示 error toast,允许重试 |
