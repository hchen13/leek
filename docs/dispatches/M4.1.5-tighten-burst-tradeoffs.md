## 3 任务

### Task 1: `CODEX_MAX_CONCURRENT` 3 → 5

**症状**:C1 23 个 agent_queued event,nested subagent(comparison + 3 quick-screen + main = 4 子 + 1 主)5 路 codex 全部争 3 个 slot,严重排队。

**修法**:`api/mod.rs::CODEX_MAX_CONCURRENT` 3 → 5。覆盖:
- 主 agent
- comparison 子 agent
- 最多 3 个并发 quick-screen / corpus-expert(同 task 一发)

5 slot 在嵌套场景下不再 contend;同时仍 限单用户 burst 防 codex API rate-limit。

单测:`codex_semaphore_caps_at_five_concurrent`(6 并发 → 1 queue)。

### Task 2: `wall_deadline` 加入 stream poll select!

**症状**:C2 backend 卡 12+ 分钟无事件,wall_clock cap 1800s 应该 fire 但只在 iter 顶检,**单 iter 内 codex stream 死寂**就检不到。

**修法**:loop_core.rs 内 stream poll `tokio::select!`(M4.1.3 改成 4-arm)再加一臂 `wall_deadline_fut`,跟现有 `idle_fut` 类似但用 `wall_deadline`(turn 级):

```rust
let wall_fut = async {
    match wall_deadline {
        Some(d) => tokio::time::sleep_until(d).await,
        None => std::future::pending().await,
    }
};

tokio::select! {
    biased;
    _ = notify_fut => PollOutcome::Aborted,
    _ = idle_fut => PollOutcome::IdleHit,
    _ = wall_fut => PollOutcome::WallClockHit,  // ⭐ 新加
    _ = sleep_until(heartbeat_deadline) => PollOutcome::Heartbeat,
    item = stream.next() => PollOutcome::Item(item),
};
```

`WallClockHit` arm break 'stream + 设 stop_reason = "wall_clock_exceeded"。

iter 顶的 wall_deadline 检查保留(防 stream 没启动时也能 cap),mid-stream 加一道。

单测:mock stream 跑 1801s 不 emit 完成 → break + stop_reason 正确。

### Task 3: `max_tool_calls_per_turn` 新硬 cap

**症状**:A4 (round 1 + 3 都 fail) — main agent + medium effort 把"看 60 天事件"过度 over-think 14 个 tool calls 没收尾。iter cap = 50 + cost cap = $5 + wall_clock = 1800s 都没救。

**修法**:加一个新 guard `max_tool_calls_per_turn`(default 30 for main / per-agent override in AGENT.md frontmatter)。

实现:
- `guards.rs::GuardConfig` 加 `pub max_tool_calls: Option<usize>`
- `Config` 加 `max_tool_calls_per_turn` 字段 + `Some(30)` resolver default
- `loop_core.rs` 每次 tool 调用后递增 `tool_call_count_so_far`,check >= cap → break + stop_reason = "tool_call_cap_exceeded"
- 5 内置 AGENT.md frontmatter 加 `max_tool_calls`:
  - quick-screen: 8(轻量,几次工具就该写答)
  - comparison: 25(并行多 task)
  - deep-review: 40(深度允许多)
  - corpus-expert: 12
  - general-purpose: 30(default)

stop_reason 字符串`tool_call_cap_exceeded`(M2.6 没这个,新加)+ assistant 兜底文案"工具调用达上限,基于已收集数据先给阶段结论"。

单测:mock loop 调 31 tool calls → break + stop_reason 正确。
