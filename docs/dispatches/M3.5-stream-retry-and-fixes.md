## Scope

### A. SSE stream layer 加 retry(critical path)

当前 `crates/gateway/src/llm/codex.rs::chat()` 返回 Stream 后,stream 中段 error (`reading SSE chunk` / `request or response body error` / `operation timed out`)直接传给 caller,不走 retry。

**改**:`chat()` 返一个**自动 retry 的 stream wrapper**,内部:
1. 启动 first stream attempt
2. Stream 中段 error → 判 classify(stream_timeout / stream_decode_error)
3. 若 retryable + 还有 retry budget → emit `provider_retry_attempt` event → backoff sleep → 重新 POST chat,**带相同 input 数组** → 拿新 stream → 继续 yield events
4. **关键**:已 yield 给 caller 的 events 不撤回(主 agent loop 看到的 partial state 保留)。新 stream 从头开始,但 agent loop 会**忽略 duplicate Usage events** + 把 final answer 用最新 stream 的

实施 hint(executor 自由发挥):
- 在 loop_core / mod.rs 主循环外加一层 retry wrapper — agent loop 看到的是"一次 chat call",内部 retry transparent
- 或者 chat() 返 `Box<dyn Stream>` 包装,内部状态机管 retry
- 注意 partial token usage 计数 — 不要 double-count

新 FatalReason kind:
- `CodexStreamTimeout` — SSE stream read 操作超时
- `CodexStreamDecodeError` — 收到 byte 但 JSON parse 失败

### B. retry 增强(参数调整)

`crates/gateway/src/llm/retry.rs`:
- `MAX_ATTEMPTS: 3 → 5`
- `BACKOFFS: [1s, 4s] → [1s, 5s, 15s, 30s, 60s]`(5 attempts,4 backoff slots)
- 总等待 worst case ~111s 加上每 attempt request lifetime(connect 30s + read upper limits)
- 单 attempt timeout 仍 reqwest 300s overall(M3.4 加的)

retry 适用 fatal kind 扩展:
- 之前:`CodexHttp5xx`, `CodexConnectionFailed`(silent 暂未做)
- 新加:`CodexStreamTimeout`, `CodexStreamDecodeError`(都是 transient,通常 retry 就 OK)

### C. chat 加 "重试本回合" 按钮(M3.3 deferred 的)

`frontend/web/src/Chat.tsx` 的 `renderFatalCard`:已显示 hint + kind + detail,**加按钮**:

```
[ 🔄 重试本回合 ]   [ 继续提问 (跳过) ]
```

点 "重试本回合" → 找到 turn 对应的 user message 内容 → POST 新 message 到 same session(等同于 user 复制粘贴重发,但 1 click)→ 关掉这个 fatal card

工程实现简单:`renderFatalCard` 加个 button,onClick 找 `messages[index-1]` (上一条 user message) content → fetch POST.

### D. M3.1 codex_duplicate_abort 对 subagent 改 warn-only

`crates/gateway/src/agent/builtin_governance.rs`:

当前:warn ≥ 3 / abort ≥ 7。subagent loop 跑 deep-review 时,**反复 read 同一 PDF 多 chunks 是正常**(spec §G 暗示);现在被 abort 触发误伤(T31 实测 abort 在 iter 11)。

修法:
- subagent loop spawn 时,**给 BuiltinTracker 传 `is_subagent: true` 标志**
- 如果 is_subagent + signal == Abort → 降级为 Warn(不 drop stream,继续跑)+ emit warning event 提示用户可知
- 主 agent 行为不变(abort 仍然触发)

或者更简单:**deep-review / comparison / general-purpose subagent 默认禁用 abort 阈值**(只 warn);quick-screen / corpus-expert 保留(它们短任务)。

实施由 executor 选,关键:**T31 deep-review subagent 不再被 codex_duplicate_abort 强杀**。
