调研日期 2026-05-24。Source:

实施时如果 spec 跟下面 CC 实情冲突,以下面为准。

## 1. SKILL.md frontmatter

字段(全部 optional 除 `description` 推荐)。

| Field | leek 处理 |
|---|---|
| `name` | 默认 = 父目录名,lowercase / hyphens / max 64;leek 同 |
| `description` | 进 system prompt 索引,CC 截断 1,536 chars;leek 全文进索引(我们规模小) |
| `when_to_use` | 同 description 拼接;leek 暂不接(MVP) |
| `disable-model-invocation` | true → 不进 model 索引,只 user `/name` 触发;leek 同(无前端 `/` UI,仍可通过 `use_skill(name)` 手动调) |
| `user-invocable` | false → 不进 `/` 菜单,model 可调;leek MVP 不接 |
| `allowed-tools` | 空格 / YAML list;skill active 时 pre-approved。**CC 不强制 set-intersection**(其他工具仍可调,只是需要 user 同意)。leek 也走 advisory(不收紧 set),仅 surface 到 prompt 让模型自己遵守 |
| `argument-hint`, `arguments` | `$ARGUMENTS` 替换;leek MVP 不接(`use_skill` 不带 args) |
| `model`, `effort`, `context`, `agent` | model override / forked subagent;leek 不接(单 model + 无 subagent) |
| `hooks` | skill-scoped hooks;leek 不接(MVP 只 global hooks) |
| `paths` | glob 限制 auto-load;leek 不接 |

**spec 偏差**:spec 写"该 turn 内 skill body 加载后后续 iter 收紧 set",CC 实际 advisory 不强制(`allowed-tools` 是 pre-approve permission,不是约束)。**采用 CC 语义**:leek 仅在 prompt 列出该 skill 推荐的 tools,不做硬性 intersection,避免误伤主 loop 工具调度。

## 2. use_skill / Skill 工具调用语义

CC 的 `Skill` 是一个 user-facing 工具(model 通过 ToolUse 调,user 通过 `/name`)。**body 一次性 inject 当前 turn 上下文,后续 turn 不复读**(Skill content lifecycle 段)。

leek 实现:`use_skill(name: string)` → 返 markdown body 作为 `model_output`。下一 iter 模型 input 中即可见 body(走现有 `function_call_output` 通道,不需额外注入)。`display_payload` 出 `card_kind = "skill_invocation"`,canvas 显示卡片。

**关键决策**:不在 leek 内做"compaction 跨阶段 re-attach 5,000 token"逻辑(M2.5 复杂度太高,CC 用 25,000 共享 budget)。skill body 走普通 message → 普通 compaction 路径。

## 3. Hook 配置位置

CC 在 `~/.claude/settings.json` 或 `.claude/settings.json` 配 hook。

leek 复用 `~/.leek/config.json`(本 dispatch 自带 minimal config 加载,M2.6 settings UI 是另外 dispatch)。结构 与 CC 对齐:

```json
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "web_fetch", "hooks": [{ "type": "command", "command": "...", "timeout": 60 }] }
    ]
  }
}
```

注意:CC 的外层是 event → array of `{ matcher, hooks: [...] }`,内层 `hooks` 才是真 hook 配置。**采用 CC 嵌套结构**(更易迁移)。

## 4. Hook event payload schema

CC 共 22 个 event,leek MVP 实现 **7 个**(去掉跟 leek 架构无关的:`PermissionRequest` / `PermissionDenied` / `Elicitation*` / `CwdChanged` / `FileChanged` / `ConfigChange` / `InstructionsLoaded` / `Setup` / `UserPromptExpansion` / `PostToolBatch` / `WorktreeCreate` / `SubagentStart` / `StopFailure` / `PostToolUseFailure` / `Notification` MVP)。

| Event | leek payload(对齐 CC 字段名) |
|---|---|
| `SessionStart` | `{ session_id, hook_event_name, source: "startup" }` |
| `SessionEnd` | `{ session_id, hook_event_name, session_end_reason: "manual" }` |
| `UserPromptSubmit` | `{ session_id, turn_id, hook_event_name, prompt }` |
| `PreToolUse` | `{ session_id, turn_id, iteration, hook_event_name, tool_name, tool_input, tool_use_id }` |
| `PostToolUse` | `{ session_id, turn_id, iteration, hook_event_name, tool_name, tool_input, tool_result, tool_use_id }` |
| `PreCompact` | `{ session_id, turn_id, hook_event_name, compaction_trigger: "auto", tokens_before }` |
| `Stop` | `{ session_id, turn_id, hook_event_name, response, stop_reason }` |

`SubagentStop` / `Notification` event type 在 engine 中注册但目前没触发点(M2.7 / 用户自定义后续接)。

## 5. Hook output / exit code 语义

| 出 channel | 含义 |
|---|---|
| exit 0 + stdout JSON | parse 成 `HookOutput`;`hookSpecificOutput.permissionDecision = "deny"` → block(PreToolUse);top-level `decision = "block"` → block(UserPromptSubmit / Stop / PreCompact)|
| exit 0 + stdout 非 JSON | Continue(忽略 stdout) |
| **exit 2** | Block,stderr 反馈给 model |
| 其他 exit | Non-blocking error,只 log |

leek 实现 `HookOutcome::{ Continue, Block { reason }, ContextInjection { text } }` 三态。Modify payload(`updatedInput`)scope 内不实现(advanced),只 log。

## 6. Plugin manifest

CC 用 `.claude-plugin/plugin.json`(注意是 .claude-plugin 子目录,manifest 在里面)。leek **复用 CC 路径**:`~/.leek/plugins/<name>/.claude-plugin/plugin.json` + `<project>/.claude/plugins/...`(对齐 CC 用户已习惯)。

| Field | 必需 | leek 处理 |
|---|---|---|
| `name` | required | skill 命名空间前缀,但 leek MVP **不做 namespacing**(直接 skill 名平铺,冲突时 plugin < user < project),保持简单 |
| `description` | optional | log 显示 |
| `version` | optional | log 显示 |
| `author` | optional | log 显示 |

Plugin 目录布局(CC 完全一致):

```
<plugin>/
├── .claude-plugin/plugin.json
├── skills/<skill-name>/SKILL.md
└── hooks/hooks.json    # { "hooks": { ... } } 同 settings.json hooks 段格式
```

plugin 内 skills 走 user-layer 优先级合并(项目 > 用户/plugin > 内置)。plugin 内 hooks 同 merge 进 effective hooks list。

## 7. 不做(MVP 偏离 CC)

1. **plugin name space**(`/plugin-name:skill-name`)— leek 单平铺,简化 use_skill 调用。
2. **skill `context: fork`**(forked subagent)— M2.7 subagent 没接。
3. **skill `$ARGUMENTS`** 替换 — use_skill 暂不带 args。
4. **dynamic context injection**(`` !`<cmd>` `` skill body 内 inline shell)— 安全性 + 复杂度。
5. **subagent / MCP / LSP / monitors / bin** — 全部超出 scope。
6. **`disableSkillShellExecution` / `skillOverrides` settings** — 没必要(我们没 inline shell)。
7. **hook 高级 type:`http` / `mcp_tool` / `prompt` / `agent`** — 只支持 `command`。
8. **`updatedInput` / `additionalContext` 注入主上下文** — MVP 不做(只 log + block / continue)。
