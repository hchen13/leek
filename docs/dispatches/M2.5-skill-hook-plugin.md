## Scope

### A. Skill System

#### A.1 文件结构

**三层发现路径(ARCHITECTURE §9 已 locked)**:
- 内置:`harness/skills/<name>/SKILL.md`(跟 repo 走)
- 用户全局:`~/.leek/skills/<name>/SKILL.md`(第三方安装)
- 项目级:`<project>/.leek/skills/<name>/SKILL.md`(项目自带)

同名冲突优先级:项目 > 用户 > 内置。**所有层进 skill 索引**。

#### A.2 SKILL.md 文件格式

```yaml
---
name: <skill-name>            # required, 唯一标识(用于 use_skill 调用)
description: <一句话>          # required, 进 system prompt 索引
allowed_tools: [...]           # optional, 该 skill body 内的工具调用受限
paths: [...]                   # optional, 该 skill 关联的相关文件 paths(可选 affordance)
disable-model-invocation: bool # optional, true = 不进索引(用户手动 use_skill 才用)
model: <override>              # optional, codex pro 单 model 时无视
---

<markdown body — 通过 use_skill 懒加载>
```

#### A.3 加载链路

新 `crates/gateway/src/skills/` 目录:

- `loader.rs`:
  - 启动时扫描三层目录
  - 解析 SKILL.md frontmatter + body
  - 三层合并 + 优先级处理
  - 构建 `SkillRegistry: Arc<HashMap<String, Skill>>`,放 AppState
- `skill.rs`:`Skill` struct(name / description / allowed_tools / body / source_layer / model)
- 热加载:`notify` crate 监听三层目录,改动重 load(MVP 可省略,留 TODO,但 listing 进 spec)

#### A.4 System prompt 索引注入

`crates/gateway/src/agent/prompt.rs` 当前五段顺序(M2 已落):
```
IDENTITY → OPERATING → 求证纪律 → corpus orientation → 可用工具
```

加新一段 **Skills 索引**,位置:**可用工具之后**(因为 skill 比 tool 更"软"/更可选)。

Skill 索引格式(只 description,**不 body** —— 懒加载):
```
## 可用 Skills

懒加载式专业上下文。需要时调 use_skill 工具,把对应 skill 的完整指南
加进当前 iter 的 context。

- skill-a — <description>
- skill-b — <description>
- ...
```

`disable-model-invocation: true` 的 skill **不进索引**(只能用户手动 use_skill 触发,模型看不到)。

#### A.5 `use_skill` 工具

新工具 `crates/gateway/src/agent/tools/use_skill.rs`,加入 `tools::specs()` / `tools::dispatch()`:

签名:
```
use_skill(name: string) → { skill_name, body, allowed_tools }
```

调用语义(CC 调研确认细节):
- 返回 skill body 作为 model_output → 模型在当前 iter response 后,下一 iter 就能看到 body 在 input
- `display_payload`:`kind="skill_invocation"`,canvas 显示 "加载 skill: <name>" 卡片(可展开 body preview)
- skill body 加载后,**该 turn 内的后续 iter** 工具调用受 skill `allowed_tools` 限制
  - 实现:在 agent loop 维护 `active_skills: Vec<Skill>`,每次 iter 之前根据 active skills 收紧
    available tools(set intersection)
  - turn 结束清空 active_skills

#### A.6 内置 skill

leek 自带至少 2 个 skill 作为参考实现 / 内部用:

1. `harness/skills/corpus-research/SKILL.md`:
   - description: "如何用 corpus_search + corpus_read 做投研主题深度研究"
   - body: 具体使用心法(先 search 拿 hits,再 read 关键 doc,引用要带 path,等)
2. `harness/skills/web-research/SKILL.md`:
   - description: "如何用 web_search + web_fetch 做事实求证 / 时效性查询"
   - body: 求证纪律的执行指南细节

这两个 skill 既是用法示范,也是 M2.5 Skill 系统的 e2e 验证用例。

### B. Hook System

#### B.1 9 个 event types(CC 对齐)

| Event | 触发时机 | Payload (typical) |
|---|---|---|
| `SessionStart` | session 创建 | session_id, user_id |
| `SessionEnd` | session 关闭 | session_id |
| `UserPromptSubmit` | user 发 prompt 后,模型调用前 | session_id, turn_id, user_message |
| `PreToolUse` | 工具调用前 | session_id, turn_id, iteration, tool_name, args |
| `PostToolUse` | 工具调用后 | session_id, turn_id, iteration, tool_name, args, result, error |
| `PreCompact` | auto-compaction 触发前 | session_id, turn_id, tokens_before |
| `Stop` | turn 结束 | session_id, turn_id, stop_reason |
| `SubagentStop` | subagent turn 结束(M2.7 才有用,但 spec 落) | parent_turn_id, subagent_turn_id |
| `Notification` | 任意可观测信号(用户自定义触发) | message |

**调研 CC 时确认上面 payload 详细 schema**,以 CC 为准。

#### B.2 Hook 配置

CC 在 `~/.claude/settings.json` 配 hook。leek 复用 `~/.leek/config.json`(M2.6 已建)加 `hooks` 字段:

```json
{
  "cost_cap_usd": 5.0,
  "...其他 settings 字段...",
  "hooks": {
    "PreToolUse": [
      { "command": "echo 'about to call tool' >> /tmp/leek.log", "timeout": 10 }
    ],
    "PostToolUse": [
      { "matcher": { "tool_name": "web_fetch" }, "command": "...", "timeout": 30 }
    ]
  }
}
```

`matcher`:可选,根据 payload 字段过滤(CC 有这个,scope 内做基本支持)。
`timeout`:可选,默认 60 秒。
`command`:必填,shell 命令,通过 `sh -c <cmd>` 跑。

#### B.3 Hook 执行 engine

新 `crates/gateway/src/hooks/` 目录:

- `engine.rs`:
  - `HookEngine::trigger(event_type, payload) -> Result<HookOutcome>` 由 agent loop 在各 event 点调用
  - 找到 match 的 hook(matcher 过滤后),按 settings.json 中顺序串行执行
  - 每个 hook:`sh -c <command>` + stdin 喂 payload JSON + 捕获 stdout JSON + exit code + timeout
- `outcome.rs`:
  - `HookOutcome::Continue` — 默认,什么都不做
  - `HookOutcome::Block { reason }` — exit code != 0 时,中止当前 agent 动作(比如 PreToolUse block 会取消该 tool call)
  - `HookOutcome::Modify { new_payload }` — stdout 返非空 JSON 时,替换 payload(advanced,CC 怎么做参考调研)

#### B.4 集成点

在以下 agent loop 位置调用 `HookEngine::trigger`:

| 位置 | 文件 | event |
|---|---|---|
| `drive()` 开始 | mod.rs | SessionStart(如果是 session 第一 turn)/ UserPromptSubmit |
| iter loop 之前 tool dispatch | mod.rs | PreToolUse → 可 block |
| tool dispatch 之后 | mod.rs | PostToolUse |
| compaction 触发 | mod.rs | PreCompact |
| `drive()` 结束 | mod.rs | Stop |
| (session 关闭 by API) | api/sessions.rs | SessionEnd |
| subagent 完 | (M2.7 才接) | SubagentStop |
| 用户自定义触发 | (后续,可不做) | Notification |

#### B.5 Block 行为细节

- `PreToolUse` block → 跳过该 tool call,emit `tool_blocked_by_hook` event,继续后续 iter
- `UserPromptSubmit` block → 拒绝整个 turn,直接 stop_reason = "blocked_by_hook"
- 其他 event block 是 advisory(只 log,不 actually block,因为已经发生)

### C. Plugin System

#### C.1 Plugin 结构

Plugin = skill bundle + hook bundle + manifest:

```
~/.leek/plugins/my-plugin/
├── plugin.json
├── skills/
│   ├── skill-a/
│   │   └── SKILL.md
│   └── skill-b/
│       └── SKILL.md
└── hooks.json    # 同 config.json 中 hooks 字段格式
```

#### C.2 plugin.json manifest

```json
{
  "name": "my-plugin",
  "version": "1.0.0",
  "description": "...",
  "author": "...",
  "skills": ["skill-a", "skill-b"],  // 显式 enable
  "hooks_file": "hooks.json"          // 显式指向 hook 文件
}
```

#### C.3 加载链路

新 `crates/gateway/src/plugins/`:

- `loader.rs`:启动时扫描 `~/.leek/plugins/` 下所有目录 + `<project>/.leek/plugins/`
- 每个 plugin.json 解析后:
  - skills 目录下的 SKILL.md 加入 SkillRegistry(优先级 = 用户层)
  - hooks.json 内容 merge 进 effective hooks(plugin hooks 在 config.json hooks 之后执行)
- 失败的 plugin(manifest invalid / skill 加载失败)warn log + skip,不阻塞启动

#### C.4 不做(v0)

- **不做远程 plugin marketplace**(只本地安装)
- **不做 plugin 沙箱**(MILESTONES open question, "只信本地安装")
- **不做 plugin enable/disable UI**(用户手动放进 plugins/ 目录就 enable)

### D. 不做(全 milestone 范围)

- **不引 V8 / Wasm 跑 hook**(只 shell command,CC 也是这样)
- **不实现 Skill body 编辑器 UI**(corpus 也是 git 管理,skill 同理)
- **不动 M2.7 subagent**(skill 系统是 subagent persona 绑定基础,但 subagent 本身另外 dispatch)
- **`PreToolUse` block 之外的 advisory event 不实现真正的"修改 payload"语义**(scope 内只 log + continue)
- **不删 env var override**(M2.6 settings 已建立的 env > config > default 链路保留)

### E. API endpoints

`GET /api/v1/skills` → 返当前 skill registry list(name + description + source_layer)
`GET /api/v1/skills/<name>` → 返 skill 完整 metadata + body(供前端预览,不算 use_skill)
`GET /api/v1/hooks` → 返当前 effective hooks list(包含 matcher + timeout,不含 command 实际内容?CC 有什么暴露?)
`GET /api/v1/plugins` → 返已加载 plugin list

(API 主要供前端 Settings UI 和未来的 plugin manager 用,scope 内只暴露 read,不做 install API。)
