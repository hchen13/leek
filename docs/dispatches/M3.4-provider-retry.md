## Scope

### A. reqwest 层 timeout 紧逼

`crates/gateway/src/llm/codex.rs` 的 reqwest::Client builder:

```rust
ClientBuilder::new()
    .connect_timeout(Duration::from_secs(30))  // 连接 30s 没建好 → fail
    .timeout(Duration::from_secs(300))         // 整个 request 5 min cap
    .pool_idle_timeout(Duration::from_secs(60))
    .build()
```

- `connect_timeout`:TCP/TLS handshake 30s 没成功 → reqwest 自己抛 timeout 错(不再死等)
- `timeout`(overall):整个 request lifetime cap 5 分钟 — xhigh reasoning + 30 次 builtin search 实测最长 turn 7 iter / 5 分 41 秒,**每 iter** 给 5 分钟绰绰有余(实际正常 iter 5-60 秒)
- 不动 SSE 层 idle 检测(M3.3 已修,保留)

executor 自由调整(如果 reqwest API 不同),核心:**让任何 codex 调用最多 5 分钟,不能死等更久**。

### B. 自动重试机制

新 `crates/gateway/src/llm/retry.rs`(或 inline 到 codex.rs):

```rust
async fn call_with_retry(client, request) -> Result<...> {
    let max_attempts = 3;
    let backoff = [Duration::from_secs(1), Duration::from_secs(4), Duration::from_secs(16)];
    for attempt in 0..max_attempts {
        let result = inner_call(client, request).await;
        match classify(result) {
            ShouldRetry => {
                emit_retry_event(attempt, max_attempts);  // canvas note "重试中 (2/3)..."
                tokio::time::sleep(backoff[attempt]).await;
                continue;
            }
            Final(ok_or_4xx) => return ok_or_4xx,
        }
    }
}
```

**重试分类**(M3.3 FatalReason 已有 kind,复用):
- `codex_http_5xx` → **重试**(transient,vendor 抽风)
- `codex_connection_failed` → **重试**(网络抖动)
- `codex_stream_silent` → **重试 1 次**(长 reasoning 抽风,但不要无限重)
- `codex_http_4xx` → **不重试**(client error,重试也没用)
- `codex_malformed` → **不重试**(leek 自己 bug)

事件:每次重试 emit 一个新 event kind `provider_retry_attempt`(canvas surface),前端 Chat 渲染:

```
⏳ codex 暂时不可用,重试中(第 2/3 次)... 等 4 秒
```

后端 retry 透明:agent loop 不知道有重试,只看到最终成功或最终 fail。
