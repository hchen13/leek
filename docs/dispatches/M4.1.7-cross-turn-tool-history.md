# M4.1.7 — 跨 turn tool history 持久化(对齐标准 agent loop)

> **Dispatch spec(2026-05-28)。** User 实测 session `s-09530706763349008ccde5ab3f187003` 暴露 leek 严重 harness 设计偏差:**跨 turn 完全丢 tool history**。turn 2 model 看不到 turn 1 调过 market_overview,自然重复调。Claude Code / OpenAI Assistants 标准做法都是**全 tool_use + tool_result 跨 turn 保留**(直到 context 溢出再 compact)。leek 当前是 token-efficient 的 trade-off,但**违反基本 agent loop 设计**。本次 dispatch 修对齐 standard。
>
> **不修同 turn parallel 重复 bug**(那是 model reasoning 层 + 工具描述层,M4.1.8 单独处理)。

## 现状(精确诊断)

`crates/gateway/src/agent/loop_core.rs:181`:
```rust
let mut additional_inputs: Vec<serde_json::Value> = Vec::new();  // 每 turn 从零
```

`crates/gateway/src/agent/mod.rs:91-105`:
```rust
let history = messages::list(&st.pool, session_id, None, HISTORY_LIMIT).await?;
let chat_messages: Vec<ChatMessage> = history.iter().filter_map(|m| {
    // 只从 DB 拉 user + assistant text,tool 历史完全丢失
});
```

DB schema(`vault.db messages` 表 0001_initial.sql):
- session_id / seq / role / content / created_at
- **无字段保存 tool_use / tool_result blocks**

Codex Responses API 通过 `additional_inputs` 接受 `function_call` + `function_call_output` items(已用于同 turn 跨 iter 传 tool 结果给 model)。我们需要把这些 items **持久化跨 turn**。

## 目标行为(对齐 Claude Code)

| 场景 | 当前 leek | 修后 leek | Claude Code |
|---|---|---|---|
| 同 turn 跨 iter,model 看 iter N 的 tool 结果 | ✓ via additional_inputs | ✓ unchanged | ✓ via messages array |
| 跨 turn,turn N+1 model 看 turn N 调了啥 + 结果 | ✗ **完全丢** | ✓ via 持久化 tool_dialog | ✓ via 全 messages 保留 |
| Context overflow 时 compact | M1.8 same-turn only | M1.8 + 加 tool_dialog 滑窗 | sliding summarize 全部 |

## 设计

### A. DB schema(新 migration 0007)

`crates/gateway/migrations/0007_tool_dialog.sql`:
```sql
ALTER TABLE messages ADD COLUMN tool_dialog TEXT NULL;
-- JSON array of additional_inputs items (function_call + function_call_output) 
-- for the turn that produced this assistant message. NULL for user rows + 
-- pre-M4.1.7 historical rows. Only main-agent tool dialog is persisted (subagent's
-- inner tool history stays opaque).
```

### B. agent/mod.rs::drive() 调整 2 处

**1. Turn 启动时,重建 prior_tool_dialog**:
```rust
let history = messages::list(...).await?;
let chat_messages: Vec<ChatMessage> = history.iter().filter_map(|m| {
    // 同前
}).collect();

// M4.1.7: 拉 prior turns' tool_dialog 按 seq 顺序拼接,作为 LoopParams.prior_tool_dialog
// 传给 loop_core 起点 additional_inputs。
let prior_tool_dialog: Vec<Value> = history.iter()
    .filter_map(|m| m.tool_dialog.as_deref().and_then(|s| serde_json::from_str(s).ok()))
    .flatten()
    .collect();
```

加 cap(防一个深度复盘 turn 100k tokens 撑爆下次 turn):
```rust
const PRIOR_TOOL_DIALOG_TURN_CAP: usize = 5;  // 只保留最近 5 turn
// 取 history 末尾 5 个 assistant 的 tool_dialog
```

**2. Turn finalize 时,把 outcome.tool_dialog 写进新 assistant 行**:
```rust
let assistant = messages::insert_with_tool_dialog(
    &st.pool, session_id, "assistant", &final_text,
    Some(&serde_json::to_string(&outcome.tool_dialog)?)
).await?;
```

### C. agent/loop_core.rs 调整

LoopParams 加字段:
```rust
pub prior_tool_dialog: Vec<serde_json::Value>,  // pre-seeded from prior turns
```

`run_loop` 起点:
```rust
let mut additional_inputs: Vec<serde_json::Value> = p.prior_tool_dialog.clone();
```

LoopOutcome 加字段:
```rust
pub tool_dialog: Vec<serde_json::Value>,  // full accumulated, persisted by drive
```

Return:
```rust
LoopOutcome {
    ...,
    tool_dialog: additional_inputs,  // outcome carries the full set
}
```

### D. subagent 处理

**subagent 不持久化 tool_dialog 跨 turn**:
- subagent 是临时 task,跑完 digest 给主 agent,生命周期不跨 turn
- subagent 的 `prior_tool_dialog` 永远是空 Vec(新 LoopParams default)
- subagent 内部 tool dialog 不写入 messages.tool_dialog(因为它的 final 不写 messages 行,而是通过 subagent_card 返主 agent)

`agent/subagent.rs::dispatch_subagent` 调用 `run_loop` 时:
```rust
prior_tool_dialog: Vec::new(),  // 显式空,subagent 是 stateless 跨 turn
```

### E. M1.8 compaction 集成

M1.8 现有逻辑:context tokens > threshold(default 90% of context_window)→ summarize chat_messages 早期部分。

**修改**:compaction 触发时,如果 prior_tool_dialog 大,也把它纳入 compaction(转 summary text 塞 chat_messages,删 prior_tool_dialog 中早期项)。

简化版:本次 dispatch **不改 M1.8 内部** — 改成"prior_tool_dialog 进 additional_inputs,M1.8 compaction 只动 chat_messages"。Context 真撑爆时 turn 内 M1.8 触发但只 summarize messages 不 summarize tool_dialog。如果实测出问题再单独 dispatch fix。

加 cap 已经足够防爆(5 turn 历史)。

### F. messages.rs API 调整

新方法 `messages::insert_with_tool_dialog(pool, session_id, role, content, tool_dialog_json)`:
- 当前 `messages::insert` 保留(不传 tool_dialog 用 NULL)
- 新方法 wrap 前者 + 写 column

`Message` struct 加 `pub tool_dialog: Option<String>`(JSON serialized)。

`messages::list` SELECT 加 tool_dialog 列。
