# M3.1 — codex builtin web_search 治理(duplicate URL detector + next-iter inject + abort)

> **Dispatch spec(2026-05-25)。** 修 ARCHITECTURE 层级缺陷:leek 的 5 个 guards
> (idle/wall/iter/doom/cost)全部对 **codex 服务端 builtin tools** 失效。M3 deep-review
> eval session 在长电科技(600584)上踩雷:同一 PDF 被 codex 内部 `open_page` × 9 次,
> 另一 PDF × 5 次,user 等 12 分钟无反馈无干预手段。

## 背景

### 失败案例(实测)

```
event 数:155 (turn 已 12+ 分钟仍 running)
search_lifecycle.completion + action_type=open_page URL 分布:
   9  https://static.cninfo.com.cn/.../1225091498.PDF   ← 重复 9 次
   5  https://stockmc.xueqiu.com/.../600584_20260429.pdf  ← 重复 5 次
   2  https://static.cninfo.com.cn/.../1225224901.PDF
   1  prnewswire / xueqiu / cninfo / tsmc / sina ...

leek-side web_fetch URL 分布:
   1  jcetglobal.com/...id=2037
   1  jcetglobal.com/...high-performance-computing
   1  sina.com.cn/.../12075299
   → 3 个不同 URL,各 1 次,0 重复 ✓ (doom_loop 在 leek-side 工作正常)
```

leek-side 工具 doom-loop 完全工作,**问题在 codex builtin web_search 服务端循环**。

### Architecture 根因

codex Responses API request → response 单向流。builtin tool(`web_search`)决策完全在
codex 服务端 — leek 只能通过 SSE `web_search_call` event mirror 已发生的事。**无反向
通道告知模型 "stop"**。

leek 能做的 3 个层次(从严到松):

| 层 | 描述 | 可行性 |
|---|---|---|
| **L1** in-loop 告知 model "别 read 第 10 次了" | ❌ codex API 无 inject 入口 |
| **L2** abort 整个 iter(drop SSE stream)| 🟡 能,但 nuclear — 丢全 iter 工作 |
| **L3** next-iter 之前 inject system 提示 | ✅ agent loop 边界有控制权,完全可行 |

本 dispatch 实施 **L3(核心)+ L2(高阈值兜底)+ 实时 warning event 给 UI**,让 user
实时看到 + 模型自纠 + 极端情况强制停。

## Scope

### A. Backend — per-turn duplicate URL tracker

新 `crates/gateway/src/agent/builtin_governance.rs`:

```rust
pub struct BuiltinTracker {
    /// (action_type, url) → 计数,action_type ∈ {"open_page", "find_in_page", "search"}
    url_counts: HashMap<(String, String), u32>,
    /// 已 warn 过的 key,防重复 emit
    warned: HashSet<(String, String)>,
    /// 已 abort 过的 key,防多次触发
    aborted: bool,
    warn_threshold: u32,
    abort_threshold: u32,  // 0 = 关闭 abort
}

impl BuiltinTracker {
    pub fn new(warn: u32, abort: u32) -> Self;

    /// observe a search_lifecycle completion event;返回是否要 emit warning 或 abort
    pub fn observe(&mut self, action_type: &str, url: &str) -> Option<TrackerSignal>;

    /// 在 iter 结束、下个 iter 之前调用。返回 inject 消息内容(None = 没东西要 inject)
    pub fn drain_for_inject(&mut self) -> Option<String>;
}

pub enum TrackerSignal {
    Warn { action_type: String, url: String, count: u32 },
    Abort { action_type: String, url: String, count: u32 },
}
```

逻辑:
- `observe` 每 event 调一次,counter++;若 count 跨过 warn 阈值且未 warned → Warn signal;
  若 count 跨过 abort 阈值 → Abort signal(单次)
- `drain_for_inject` 返回当前所有 warned URL 的清单(用于 inject 给下个 iter)

### B. Backend — loop_core 集成

`crates/gateway/src/agent/loop_core.rs`:

每 turn 创建一个 `BuiltinTracker`(以 Settings 中阈值初始化)。

主循环里:
- 每收到 `search_lifecycle` event(从 codex SSE 解析出来的)调 `tracker.observe()`
- `Warn` 信号 → emit `codex_duplicate_url_warning` event(canvas surface)
- `Abort` 信号 → drop iter stream(类似 idle_timeout 路径),turn stop_reason
  = `codex_duplicate_abort`
- iter 结束(`response.completed`)之后,在拼下个 iter 的 input 之前,调
  `tracker.drain_for_inject()` → inject 消息加进 `additional_inputs` 作为
  function_call_output(挂在前一个 web_search_call 的 call_id 之后,符合 Responses API spec)

inject 消息(中文,引导但不命令):

```
⚠ 在前面的 iteration 中,你重复 open 了以下页面(codex 内置 web_search):
- https://static.cninfo.com.cn/.../1225091498.PDF (9 次)
- https://stockmc.xueqiu.com/.../600584_20260429.pdf (5 次)

这通常意味着你已经从这些资源获取了足够信息。请基于已有信息得出结论,
不要再 search 或 open 同一 URL,进入综合 + 输出阶段。
```

**不阻断模型决策,只是 hint**。模型仍可自由选择下一动作。

### H. 不做(scope 内明示)

- 不做 leek-side web_search wrapper(独立 M3.x 立项)
- 不监听 leek-side `web_fetch` 重复(doom_loop 已管)
- 不做 cross-iter inject debouncing(每 iter 都 inject 一次,简单)
- 不做 abort 后 graceful retry(abort = iter 失败,后续按 stop_reason 处理)
- 不试图实现 L1(in-loop 干预模型)— API 限制
- 不动 codex `include` 参数 / web_search builtin 调用方式
