## 用户要的最终形态

### 整体布局
- **最左** vertical Navbar:`chat` 图标(目前只有 1 个 tab),左下角 `settings`
- **3 列主体**:
  - **左** Chat box — session list **不常驻**(点击图标弹出 drawer/popover)
  - **中** Canvas — agent 思路 + tool use 卡片(per-tool 视觉,变宽度)
  - **右** Sidebar — corpus map + TODO/Plan(都空时不显示)

### Canvas 卡片
- **每工具自己的 UI 组件**,不要 raw JSON
- **大部分 view-only**;少数交互(K 线换周期 — 额外 data API,**不进 LLM context**)
- **变宽度**,根据内容 fit 而非全 canvas 宽

## 实施 4 phase 分批

### Phase 1 — 布局 shell + Card 框架(M4.2.1)
- App.tsx 重写为 grid shell
- Rail(左 vertical navbar):chat 图标 + settings 图标
- 3-column 主区(chat / canvas / sidebar)
- Session list drawer(默认折叠,点击展开)
- 右 Sidebar:corpus map(已有 CorpusBrain.tsx)+ Plan widget(已有 PlanWidget.tsx)合并展示,空时整体隐藏
- CardShell 组件:统一 header(图标 + 标题 + 状态 + copy + raw-toggle 按钮)+ slot for 内容 + variable width via CSS class
- Canvas 主区按卡片瀑布流(垂直 list,卡片自适应宽度 maxWidth)
- 不动 store.ts / SSE 接入(M0-M3 已稳)
- 暂时用 GenericCard(raw JSON fallback)填所有工具 — phase 2 再换 per-tool

scope ~800-1200 LOC frontend(rewrite App.tsx + 新文件)

### Phase 2 — 9 个 facts-only 工具 per-tool Card(M4.2.2)
- 实施上表 9 工具各自的 Card 组件
- 把 main 分支 ArtifactCards.tsx 的 `CorpusSearchCard` / `CorpusReadCard` / `WebFetchCard` 直接 port(字段没变)
- 新建 9 个新 Card 文件
- 加 `lightweight-charts` 依赖

scope ~2500-3500 LOC frontend

### Phase 3 — chart_data 后端交互端点(M4.2.3)
- 新 `POST /api/v1/chart_data` 直接调用端点(不经 LLM)
- 前端 K 线 Card 用此端点切换周期
- **重要**:此端点不写 messages 表、不计入 LLM context、不 emit events
- 仅供前端图表交互用

scope ~150 LOC backend

### Phase 4 — Polish + 主题(M4.2.4)
- design token 系统(颜色 / 间距 / 字体)
- 涨跌色:**红涨绿跌(中国习惯)**
- 暗色 default + 亮色二选一
- 微交互(hover / focus / transition)
- empty state / loading / error 全套

scope ~600 LOC frontend
